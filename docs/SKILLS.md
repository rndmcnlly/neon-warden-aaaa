## Promotion gate: candidates only

contract-aware integration and honest freshness; direction-first contextual audition.
None is approved for global promotion.

Before proposing promotion:

1. Record real reuse across **distinct tasks/projects**, including a failure or
   meaningful variation, not just two prompted routing simulations.
2. Separate portable agent capability from Adam-specific coordination/taste.
3. Remove absolute/project assumptions only after the replacement works elsewhere;
   retain canonical CLI ownership instead of copying scripts into prose.
4. Preserve source artifacts, commits, dates, limitations and foreign attribution.
5. Obtain the owner's explicit approval **before** changing global skills/config.
   Consider a revision to an existing skill rather than creating another index.

Future cultivation entries should say what changed an approach and what actually
worked. Do not log routine wording edits as capability growth.
